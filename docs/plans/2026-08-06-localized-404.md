# Localized 404 / Not Found — implementation plan

Status: design complete, implementation pending  
Date: 2026-08-06

## Goal

Implement a design-system-based 404 experience for all public localized routes. Preserve the normal site shell and distinguish a missing route or Payload document from an application/server failure.

## Implementation scope

1. Build a shared presentational Not Found view exclusively from the existing shell, navigation, container, typography, button, theme and focus primitives.
2. Add Czech and English copy through the existing i18n catalogs. Do not hard-code both languages in the component.
3. Add the locale-segment Not Found boundary used by `notFound()` for valid localized routes.
4. Cover completely unmatched paths and unsupported locale segments with the root/global fallback supported by the installed Next.js version and the project's locale routing policy.
5. Ensure missing, unpublished or inaccessible Payload content calls `notFound()` before streaming where practical. Payload timeouts and exceptions remain on the error/5xx path.
6. Keep the normal header, locale switch and theme behavior. The primary recovery action returns to the homepage in the active locale.
7. Add localized metadata. Genuine Not Found responses must be non-indexable and excluded from sitemap, canonical and hreflang generation.
8. Implement route, component, accessibility, E2E and visual-regression coverage.

## Acceptance criteria

- A missing URL under every supported locale renders localized copy in the normal localized shell.
- A completely unmatched URL and unsupported locale follow the documented global/default-locale fallback; the framework-default 404 never leaks into production.
- Missing Payload content uses the same localized Not Found view. Payload/network/server failures do not masquerade as 404.
- Direct requests return an actual HTTP 404. Tests explicitly protect against a streamed Not Found response accidentally retaining status 200.
- The response has localized title/description and `noindex`; the missing URL is absent from sitemap, canonical and hreflang output.
- The page contains exactly one semantic `h1`, valid landmarks and heading order.
- The recovery action is keyboard reachable, has a visible design-system focus state and returns to the localized homepage.
- Header navigation, locale switch and theme control behave like normal pages.
- No horizontal overflow or clipped content at 320, 390, 430, 768 and 1440 px.
- Light and dark themes meet WCAG AA for text, UI and focus contrast.
- Czech and English catalog parity checks pass.
- E2E covers direct navigation, client-side navigation, recovery, keyboard focus, both locales, unsupported locale and a missing Payload record.
- Visual regression covers CS/EN × mobile/tablet/desktop × light/dark, plus the primary CTA focus state.

## Verification matrix

- Routes: valid locale + unknown path; unsupported locale; unknown root path; missing Payload slug.
- Semantics: status 404; `noindex`; localized title; no canonical to missing URL.
- Viewports: 320, 390, 430, 768, 1440.
- Themes: light, dark, forced colors where supported.
- Interaction: keyboard traversal, focus visibility, localized recovery target, mobile menu.
- Quality gates: format, typecheck, lint, unit tests, route tests, E2E, build and visual regression.

## Explicit non-goals

- Do not reuse the editorial `Content State / Error` component as the route-level 404.
- Do not convert Payload/server exceptions into Not Found responses.
- Do not create one-off colors, spacing, icons, navigation or buttons.
- Do not redirect every unknown URL to the homepage; preserve HTTP 404 semantics.
- Do not add search, animation or illustration until the core recovery flow is verified.

## Dead ends and caveats

- A locale-scoped `not-found.tsx` alone may not cover completely unmatched URLs; test the root/global fallback explicitly.
- A Not Found result produced after streaming can retain HTTP 200; resolve existence before streamed Suspense boundaries where necessary.
- Global Not Found support and required file shape depend on the installed Next.js version/configuration. Verify the actual dependency before choosing `global-not-found` versus the root boundary.
- Do not infer missing content from a caught Payload exception. Null/not-published data and operational failures require different paths.
- During planning, workspace inspection was blocked before process start by `helper_unknown_error: setup refresh had errors`; this file was therefore created as a standalone plan without modifying or guessing existing backlog sections.
