# codeguy.cz SEO Audit Plan

Status: `open` — authorizes the audit itself and the measurement-tool setup; it does not authorize code fixes.
Date: 2026-10-08

## Context

Nothing in the repository audits SEO. `docs/audits/` holds six visual-parity and E2E audits; the Lighthouse step planned in `docs/plan-analyzy.md:188` never ran; `docs/project-brief.md` §8 still describes a Czech-first, two-URL site that no longer exists; no Search Console, Bing, analytics or backlink data has ever been collected (zero hits in `docs/` and `src/`). The technical baseline is partly guarded by `src/__tests__/e2e/i18n-seo.spec.ts`, `i18n-routing.spec.ts` and `sitemap.test.ts`, but those tests never assert `og:image`, Twitter tags, structured data or performance, and they cover only Home, one case study, CV and booking.

Code reading already points at likely defects (to be confirmed against the live site, never reported from code alone): per-page `openGraph` from `src/i18n/metadata.ts:19-48` shallow-replaces the layout's `og:image`/`og:site_name`; the only social image is a square 512 px icon; no JSON-LD; no RSS; `/en/*` and `/cs/insights/:slug` redirect with 307 (`next.config.ts:55-84`); sitemap `lastModified` is request time for every static URL (`src/app/sitemap.ts:31,46`); articles cap at 100; CMS outage renders an article as HTTP 200 (`insights/[slug]/page.tsx:110-125`); `themeColor` differs between viewport and manifest; `/insights?topic=` views are not `noindex`.

Outcome: one dated, evidence-backed audit in `docs/audits/`, a working measurement stack (Search Console, Bing, field data) owned by Karel, and a severity-ordered list of proposed Linear issues. Karel decides what gets fixed.

## Goal

- Produce `docs/audits/2026-10-DD-seo-audit.md` covering every public URL of codeguy.cz in EN and CS across technical SEO, content/keywords and off-page/measurement, with each finding backed by live evidence.
- Leave Search Console and Bing Webmaster verified and the sitemap submitted, so the next audit pass has search-engine data.

## Scope

- In scope: all routes served by `https://codeguy.cz` (static pages, case studies, Insights index and every published article, CV HTML + both PDFs, `/contact/book`, 404 surfaces, `robots.txt`, `sitemap.xml`, `manifest.json`), both locales, mobile + desktop, light mode only (theme has no SEO effect). Redirect behaviour of `www`, `http`, `/en`, `/en/*`, trailing slashes, `/cs/insights/:slug`. Social previews, structured data, Core Web Vitals (lab + field), content/keyword hypotheses, internal linking, orphan pages, backlinks, profile links (LinkedIn, GitHub), analytics absence, measurement-tool setup.
- Out of scope: `jobs.codeguy.cz` (Basic auth + `noindex, nofollow` in `Caddyfile:109`; record as one KEEP finding), Payload `/admin` and `/api`, dark mode, any code change, any Figma change, keyword *volume* claims (forbidden by `docs/content/article-backlog.md:10-11` — hypotheses only until Search Console confirms), paid SEO tools.

### Task 2: Technical SEO checks

Objective:
- Confirm or refute each code-derived hypothesis against the live site; record each as a finding with evidence.

Checks (each a row in the evidence matrix):
- `og:image` / `og:site_name` present per route (hypothesis: missing on every page using `createLocalizedMetadata`); preview rendered via `https://www.opengraph.xyz` or the built-in browser + `javascript_tool` reading `<meta property>` tags; screenshot one representative.
- Social image dimensions (expect 512×512 square; standard is 1200×630).
- `og:locale:alternate` absence; `twitter:*` tags survival.
- JSON-LD: none expected (Person, WebSite, ProfilePage, BlogPosting, CreativeWork, BreadcrumbList all absent).
- Canonical ↔ hreflang reciprocity for every EN/CS pair; `x-default` → EN; CS article URL has no `cs` hreflang and 307s (L-04 contract; note 307 vs 308/301).
- `/en` and `/en/*` → 307 (`permanent:false`); recommend 308.
- Trailing slash and case normalisation behaviour.
- `robots.txt` content, sitemap URL form, `Disallow` set vs the brief's expectation.
- Sitemap: entry count, article cap of 100, `lastmod` drift, `/contact/book` inclusion (0.7) — should a booking page be in the sitemap at all? (owner decision).
- `/insights?topic=x` indexability (canonical to `/insights`, no `noindex`).
- 404 surfaces: real 404 + `noindex` + `lang` for every case in `i18n-routing.spec.ts`; the L-06 missing-article `lang` limitation re-confirmed.
- Headers: HSTS preload, `X-Robots-Tag` absent on apex (fine) and present on jobs (KEEP), `Cache-Control` on HTML (none set — note for CWV), CSP `unsafe-eval` (Best Practices score impact).
- PDFs: both CV PDFs return 200, `Content-Type: application/pdf`, no `X-Robots-Tag`; the CS/EN PDF contains the phone number (CV-04) and is therefore indexable → owner decision: `noindex` header for PDFs or accept.
- `manifest.json` `lang: en`, `theme_color` mismatch with viewport.
- CMS outage HTTP 200 — verify locally only (`pnpm start:prod` with the Postgres container on 5435 stopped; see memory [[local-production-e2e-needs-throwaway-db]]); label "verified locally, not on production".
- Mobile-friendliness: viewport meta, tap targets via Lighthouse, text wrap at 390 px in CS (already parity-tested; cite the specs rather than re-measure).
- Image alt coverage on article pages (`next/image` alt rule in `insights/[slug]/page.tsx:167`).

Validation:
- Every hypothesis in the Context section has a matrix row marked confirmed / refuted / not verified.
